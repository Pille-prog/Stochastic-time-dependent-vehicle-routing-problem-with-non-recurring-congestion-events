Powell vocabulary cheat-sheet

The four core terms (CONTEXT.md) every diagram below reuses verbatim.

TermMeaning here
StateThe information available to make a decision at a point in simulated time: vehicle positions, pending clients, observed velocities, elapsed time (tau_episode).
PolicyA rule mapping a State to a decision — which node each vehicle serves next. MonteCarloPolicy is the one live implementation.
ModelOwns the transition function: advances the State given a decision plus exogenous information (velocities, congestion). The simulator the Policy interacts with.
TrainerRuns training and evaluation Episodes over the Model to fit and compare Policies (a W weight vector, here).
EpisodeOne complete simulated run over the horizon: clients generated, congestion occurs, vehicles execute a Policy, costs accumulate.

The three variation seams ADR-0002

Everything else in the diagram below is deliberately concrete (no interface) — these three axes are the only ones designed to vary.

Policy

MonteCarloPolicy is the one live subclass of the Policy ABC. Swap in a static or Q-learning policy without touching Model.

CongestionGenerator

ArcProbabilityCongestionGenerator is the one live subclass. Model calls generate() without knowing which congestion model it got.

DataSource

CsvDataSource reads the Chengdu CSV archive today; a database-backed source could replace it without the domain model noticing.

Preserved / deliberate behaviors worth knowing: the warm-up learning rate (when configured) only applies to the very first training Episode, then learning_rate takes over from Episode 2 on. Training is always sequential — W is a serial dependency — only the evaluation blocks and the final test can spread across EpisodePool workers. The final test runs each (action count, seed) pair exactly once (ticket 02): per-Episode Generators make repeats bit-identical, so a mean over repeats would equal the single value anyway.

Training episode, step by step run_training_episode()

Note: MonteCarloPolicy.__init__ always ends by calling decide() (the greedy path), never decide_train() — that first full pass is the legacy constructor quirk. Every subsequent decision in a training Episode goes through decide_train() instead.

Evaluation & testing episode, step by step run_evaluation_episode()

Both the periodic evaluation blocks (during training) and the final test after training use the exact same path; only the seed/fleet-size/action-pool numbers differ. Batches run either in-process (EpisodeWorld) or spread across worker processes (EpisodePool) — Trainer cannot tell the difference in the results it gets back.

every mean/std the Trainer reduces is bit-identical to the serial loop's).

      MDL->>POL: decide(state) -- greedy argmin over Q = X @ W, no randomness

Evaluation blocks vs. final test: an evaluation block uses the generated fleet size and a vehicles + 2 action pool (EpisodeRequest(seed), both overrides None). The final test fixes both from config.test_vehicle_counts / config.test_action_counts — every (action count, seed) cell submitted as one 300-episode batch, so a worker pool has the whole job to spread rather than one action count at a time.

Class reference

Every class in the diagrams above, grouped by module, with its responsibility, key methods, and collaborators.

config Configuration stdvrp/config.py

ExperimentConfig frozen dataclass

Every knob of one experiment, immutable once loaded. Replaces the legacy's comma-separated sys.argv string plus values hardcoded across main()/training_and_testing/model.

  • __post_init__() — validates horizon ordering, demand/congestion ranges, positive counts, epsilon in [0,1], etc.
  • from_yaml(path) — loads + type-coerces one YAML file; rejects unknown/missing keys.
  • evaluation_seeds (property) — the fixed seed range used by every evaluation block.

Read by: ClientGenerator.from_config, CsvDataSource.from_config, Trainer.from_config, world_cache (cache-key world params).

data Network & traffic stdvrp/network/, stdvrp/traffic/

RoadNetwork network/road_network.py

The static directed graph: arc endpoints, coordinates, length in meters. Wraps the raw links table untransformed.

  • node_ids — unique arc-start nodes in file order.

TrafficHistory traffic/history.py

Raw per-day speed observations keyed by day.

  • instance_day_observations — the single day the simulation runs on.

DataSource / CsvDataSource traffic/datasource.py

ADR-0002 seam #3: the boundary through which RoadNetwork/TrafficHistory/ShortestPathCache are loaded. CsvDataSource reads the Chengdu archive's CSV naming convention.

  • load_road_network(), load_traffic_history(), load_shortest_path_cache()
  • consumed_files() — every file read, feeding the world cache's invalidation signature.

TravelTimeModel traffic/travel_time_model.py

The deterministic data spine: aggregates multi-day speed stats, fills minute gaps, interpolates three blend windows, then derives everything a Model or Policy reads.

  • Public attributes: travel_data, speed_std, successors, node_coordinates, event_probability, mean_arc_data.
  • _cached_state() / _from_cached_state() — round-trips those six attributes through the binary world cache.

Built from: RoadNetwork + TrafficHistory. Read by: EpisodeVelocities (sampling), Model, ArcProbabilityCongestionGenerator (successors/event_probability).

ShortestPathCache network/shortest_path_cache.py

Precomputed node→client shortest paths, loaded verbatim from a 907 MB CSV — never recomputed at runtime.

  • path_between(node, client) — node sequence, mean minutes, length.
  • items() — live view used by EpisodeGeometry to build its matrices without a full-dict copy.

world_cache.load_world() traffic/world_cache.py — module function

The CsvDataSource/Trainer boundary (ticket 03): builds — or reads a pickled snapshot of — the LoadedWorld(travel_time_model, shortest_path_cache) pair. Cache key hashes per-file size+mtime, the world-shaping config fields, and library versions.

EpisodeGeometry network/episode_geometry.py

ADR-0003: dense [node, client-or-depot] numpy matrices of travel minutes/length. Replaces ShortestPathCache.path_between dict lookups on the Policy's hot path. The whole-cache scan is memoized per ShortestPathCache instance; each Episode does a cheap column-select out of that shared index.

  • build(shortest_path_cache, clients, depot) — one Episode's matrices (columns: depot then that Episode's clients).
  • average_minutes / length — scalar reads (KeyError-compatible with the cache).
  • average_minutes_rows / length_rows / average_minutes_at — vectorized reads FeatureExtractor and the Policy's candidate selection build on.
demand Demand stdvrp/demand/client_generator.py

ClientGenerator

Draws one Episode's demand from its seed via a private np.random.Generator — no global random state touched.

  • generate(seed) → EpisodeDemand(clients, vehicle_count): client count (gauss, floored), node sample without replacement, per-vehicle fleet-size rounding, per-client time windows.

Client / EpisodeDemand frozen dataclasses

Client: a demand point (node + time window). EpisodeDemand: the draw's output — clients in draw order, plus the fleet size.

congestion Congestion stdvrp/congestion/generator.py

CongestionGenerator (ABC) / ArcProbabilityCongestionGenerator ADR-0002 seam #2

Non-recurring congestion events during an Episode: one uniform draw per arc of event_probability (dict insertion order matters), then per triggered event a velocity-penalty and duration draw, spread to BFS-reachable neighbors with depth-damped intensity (saturating at congestion_upper_bound).

  • generate(minute_start, congested_arcs, rng) — mutates congested_arcs in place; called only on decision epochs where congestion is "due".

Reads: TravelTimeModel's event_probability/successors. Called by: Model, once per Episode's own congestion_rng stream.

policies Policies stdvrp/policies/

Policy (ABC) base.py — ADR-0002 seam #1

Maps a State to a decision: the node each vehicle serves next.

  • decide(state) — abstract.

MonteCarloPolicy monte_carlo.py

Linear function approximation over a weight vector W: greedy argmin over predicted Q for evaluation, epsilon-greedy for training, and a Monte Carlo weight update.

  • decide(state) — greedy per-vehicle argmin, no randomness (evaluation).
  • decide_train(state) — repairs any carried-over action that's no longer feasible, then epsilon-greedy per vehicle (training).
  • update_W(states, actions, rewards) — backward Monte Carlo replay; one SGD step per decision epoch.
  • _select_vehicle_possible_actions / _closest_allowed_clients / _classify_shortest_distance_clients — candidate-action selection (normal, <3-clients-left endgame).
  • _best_q_action — prices a whole candidate set in one [candidates, 19] @ W.

Delegates to: FeatureExtractor (feature arithmetic), EpisodeGeometry (candidate-distance reads). Owns: the single exploration_rng stream.

FeatureExtractor / StateFeatures feature_extraction.py — ADR-0003

The Policy's 19-component feature vector (12 general-state + 7 state-action) as vectorized numpy arithmetic over one Episode's EpisodeGeometry. Moved out of the Policy in ticket 05 — a concrete collaborator, not a new seam.

  • state_features(state) → StateFeatures — everything the State contributes to a decision (once per decision pass, not per candidate).
  • candidate_features(features, action, vehicle, candidates) — one feature row per candidate action, vectorized.
  • action_features(features, action) — one concrete action's row (used by update_W's replay).
simulation Simulation core stdvrp/simulation/

State state.py

Mutable per-Episode information the Policy sees: vehicle positions, unvisited clients, observed velocities (per vehicle, last n_arcs arcs), terminal flag. Mutated in place by Model across the whole Episode.

TrainingSnapshot state.py — frozen dataclass

Immutable capture of the four State fields update_W's replay reads (cheaper than copy.deepcopy(state)). One snapshot taken before every training transition.

  • capture(state) — copies tau_episode, clients_not_visited, vehicle_position, observed_velocity.

Model model.py

Owns transition_function: the event-dispatch loop that advances simulated time until the Policy is owed another decision. Delegates bookkeeping to three collaborators so the transition function itself reads as pure event dispatch.

  • run_evaluation_episode() — greedy decisions until terminal.
  • run_training_episode() — epsilon-greedy Episode with per-epoch snapshots, then one policy.update_W(...) call.
  • transition_function(action) — dispatches to whichever is soonest: congestion expiry, vehicle arrival, or the next decision epoch.
  • _reroute_for / begin_arc / resample_arc / advance_clock_to — routing and clock mechanics.

Owns: CostLedger (self.costs), EpisodeVelocities (self.velocities), FleetRoutes (self.fleet). Reads: ShortestPathCache (routing node sequences), TravelTimeModel (via EpisodeVelocities). Calls: CongestionGenerator, Policy.

CostLedger cost_ledger.py Model's collaborator

Every charge the Model makes, and the running totals. A transition accumulates into transition_cost; commit_transition() folds it into total_cost — except the one legacy-preserved transition end that never commits.

  • charge_distance / charge_earliness / charge_lateness / charge_vehicle_overtime / charge_unserved_delays / charge_fleet_overtime / charge_abort_penalty.

EpisodeVelocities episode_velocities.py Model's collaborator

Samples (and memoizes per arc-even-minute) the velocity the fleet actually experiences; holds the live congested_arcs event book that CongestionGenerator writes into.

  • sample(node_start, node_end, tau_episode).
  • release() — drops the memo and event book at Episode end.

Draws from: TravelTimeModel's travel_data/speed_std, via its own velocity_rng stream.

FleetRoutes fleet_routes.py Model's collaborator

Per-vehicle struct-of-arrays: route being executed, arrival/departure clocks, distance travelled on the current arc. The Model's half of per-vehicle state; positions/directions the Policy sees stay on State.

  • earliest_arrival(), all_parked(), current_arc, next_node, advance, park.

run_evaluation_episode() / run_training_episode() episode.py — module functions

Assemble one Episode's State + EpisodeGeometry + MonteCarloPolicy + Model from a seed and the world's collaborators, run it to termination, and return an EpisodeResult (evaluation) or TrainingEpisodeResult carrying the updated W (training).

training Training orchestration stdvrp/training/

Trainer trainer.py

Runs the complete experiment one ExperimentConfig describes, over one loaded world.

  • from_config(config, cache_dir, worker_count) — loads the world, wires the EpisodePool.
  • train() — the sequential training loop with periodic evaluation blocks and best-W tracking.
  • final_test(w) — the fixed seed/fleet table at widening action pools, one batch.
  • run(output_dir) — train() + final_test() + writes results.json and the training plot.

EpisodeWorld episode_pool.py

The loaded world plus the two generators an Episode runner needs, as one value plus its keyword-argument view.

  • load(config, cache_dir), episode_kwargs(), run_episode(w, request), run_episodes(w, requests) — the serial path.

EpisodePool episode_pool.py

A persistent ProcessPoolExecutor of spawned workers, each loading its own EpisodeWorld once (from the binary cache) via the pool initializer. Memory, not cores, is the ceiling — each worker holds a full copy of the world.

  • for_worker_count(...) — None for the serial fallback (worker_count=1).
  • run(w, requests) — dispatches via Executor.map, preserving request order.

EpisodeRequest episode_pool.py — frozen dataclass

One Episode to run: its seed plus the two optional overrides (vehicle_count, number_actions_test) that distinguish an evaluation block from a final-test cell.

Result value objects trainer.py — frozen dataclasses

EvaluationBlock (one periodic evaluation's seed costs), TrainingResult (the whole training run's W trajectory + evaluations), SeedTestResult / ActionCountReport (final-test metrics per seed / per action count), ExperimentResult (everything run() produced).
